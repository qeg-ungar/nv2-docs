# Background & Motivation

## History of NV2
The setup was originally designed and built by the first generation of students in QEG. NV2 was (no surprise) the second setup constructed in QEG and is closely based on the NV1 setup, built by Clarice Aiello and Masashi Hirose. NV2 was primarily built by Alexandre Cooper (aka Alex C) and Honam Yum circa 2012. The setup design is based on a scanning confocal microscope system to image single NV centers and apply microwaves resonant with the NV spin transition in a magnetic field. One of the original scientific goals for NV2 was to perform STED micropscopy, which required the use of a high power laser (which later turned out to be needed for the SPAD array experiments). The first set of experiments, led by Alex C, were focused on Walsh spectroscopy using naturally occuring single NVs in a bulk diamond sample. 

In 2014 experiments pivoted with the fabrication of a new diamond sample called Terra-B, made in collaboration with Dr. Huiliang Zhang from Ron Walsworth's group at Harvard. This sample was ion implanted to create a matrix of arrays of NV center spots with different densities (further details on the sample are included in {doc}`Diamond Sample & PCB <../system_overview/diamond_sample_pcb>`). The motivation was to study spin polarization transfer with other nitrogen-related defects like the P1 center. To drive these other defects along with the NV spin, a two-channel microwave stripline design was created and a second microwave amplifier chain added. For the following 10 years the setup remained in a more or less steady state operation, with experiments focusing on one special NV center surrounded by several new types of defects later characterized by myself (Alex U). This phase of experiments consisted of the remainder of Alex C's PhD, Calvin Sun's PhD, and the first couple of years of my time in QEG. 

## Motivation and Goals
I felt it was necessary to create this lab manual since I have modified and upgraded the setup significantly throughout the course of my PhD. When I first entered the group, most of the setups (NV1 through NV3) were all very much alike. They were controlled and interfaced with the same MATLAB software which connected to a Tektronix AWG and NI data acquisition card. In my second year the AWG analog output panel stopped functioning on NV2, and roughly a year after that the same problem happened on NV1, rendering an end to their rather long lifetimes. It was decided we would replace the Tektronix AWG with the Quantum Machines OPX+ system, which has several advantages to be discussed in detail later on. This was a rather large overhaul of the setup, sort of like replacing the brains of the entire system. It required transitioning to a completely new software control interface run by python. It also required several other downstream changes such as replacing the photon counting interface from the NI card with the built in ADC from the OPX+. 

Since there was some down time from experiments during the OPX+ installation, I upgraded other parts of the setup which were approaching the end of their operational lifetimes and were already showing signs of damage. This included replacing the signal generator (LO) and IQ mixer stages with the two SRS-SG384 instruments, as well as replacing the high power Sprout laser with a new pulsed 100 mW laser (we later ended up using both). After we wrapped up the defect characterization project in my fourth year, we transitioned to the multiplexing project with the goal to control and image the arrays of NVs in parallel. This required adding new optics for widefield imaging as well as installing an advanced camera called a SPAD array we acquired through a collaboration with Politecnico di Milano. 

At the present stage, the setup hardly resembled the system that existed when I started my PhD. And any notes or recordings on the changes I made consisted of random screenshots or pictures uploaded to OneNote without any real organization. It was clear that in order for the setup to stay in operation when I was gone there would need to be better documentation for future students to reference. This is the central motivation behind making this lab manual. The goal is to summarize all of the hardware assemblies and operational procedures required to run and maintain the setup. This will also serve as a way for me to look back and remind myself why everything was built the way it was, since much of this documentation on the setup will end up in my PhD thesis. 

While searching for the best way to structure this manual, I came across a PhD thesis written by Zachary Vendeiro from Vladan Vuletic's lab at MIT[^vendeiro]. In Appendix B he includes a discussion on best practices for creating lab documentation. He outlines the key criteria for effective documentation, including that it's easy to share, search through for a given topic, can embed equations, figures, and other attachments, and can be easily edited. Their lab used the Confluence wiki platform set up by the MIT Center for Ultracold Atoms (CUA) for documentation as it satisfied all of these requirements, and particularly because it was easily accessed and edited by all lab members through a web browser. A lot of the style and formatting for this lab manual will be based on the Rb lab wiki written by Zach and other lab members[^CUAwiki]. 

Since this lab manual is intended to remain more or less static for future reference, the collaborative features of Confluence weren't necessary for this documentation, as opposed to a running lab log which is updated frequently by many users. Instead,  I am using the [Sphinx](https://www.sphinx-doc.org/en/master/index.html) python package to generate the html build for this site, which is published via Github Pages. The project is built locally in VS Code with assistance from a Claude agent. The Github repository for the project can be found here: <https://github.com/qeg-ungar/nv2-docs>. Future NV2 users are invited to make edits or create new modules as the setup evolves. Modifications/additions can be pushed to their local git branch and can create a pull request to merge with the main.
